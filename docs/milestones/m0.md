## Part A findings

Every item was checked by installing the packages in a scratch project and running them under Bun 1.4.4 and Node 26.12.1 on 2026-11-23. Versions are recorded in [../versions.md](../versions.md).

### Versions that are held back

- **Oxlint is pinned at 1.94.0, not 1.95.0.** `@effect/tsgo` 0.73.4 supports Oxlint 1.91 to 1.94 only.
- **tsrs is pinned at `7.1.0-beta.tsrs4`, not `tsrs5`.** `@effect/tsgo` 0.73.4 supports `tsrs2` and `tsrs4` only.

Both are pinned so that `effect-tsgo oxlint` stays usable if Effect's Oxlint rules are wanted later. Move both forward when `@effect/tsgo` lists newer versions.

### Type checking with Effect diagnostics

- `effect-tsgo tsc -p <tsconfig>` runs the Effect-patched `tsc` without changing `node_modules`. It reported a floating `Effect.log(...)` as error `floatingEffect` and exited 1. Plain `tsc` exited 0 on the same code.
- The tsconfig plugin entry is `{ "name": "@effect/language-service" }`. `effect-tsgo setup` also adds `"$schema": "./node_modules/@effect/tsgo/schema.json"`.
- `effect-tsgo patch` (via a `prepare` script) is the alternative. It rewrites `node_modules` so editors pick up the diagnostics. Not needed for the rails.
- `@effect/vitest`'s `it` raises warning `unstableApiUsage` on every test. Part B decides the severity (see B2).

### Lint: the `@cloudflare/oxlint-config` trial

Run on Effect-style code (tagged errors, `Context.Service`, `Layer`, `Schema`, `Effect.gen`, `catchTag`):

| Rule | Fired? | Action |
|---|---|---|
| `import/no-namespace` | Yes, on `import * as Schema from "effect/Schema"` | Off |
| `require-yield` | Yes, on `Effect.gen(function* () { return 1 })` | Off |
| `@nkzw/no-instanceof` | Yes | Off |
| `curly` | Yes, on `if (x) return ...` | Keep |
| `typescript/unbound-method`, `quality/no-unknown-*`, `unicorn/*` | No | Keep; revisit if they fire |

That is 3 overrides, well under the agreed limit of about 10, so the trial passes and the preset is adopted.

- Type-aware rules (`no-unsafe-*`, `no-explicit-any`, `no-floating-promises`) fire with `oxlint --type-aware` and `tsrs` installed. **`oxlint-tsgolint` is not needed.**
- Config lives in `oxlint.config.ts`, as the preset requires.
- Oxlint does not report compiler errors, so type checking stays a separate command.

### Tests

- **Vitest must run on Node, not on the Bun runtime.** `bun run vitest run` works (the binary's shebang selects Node). `bun --bun vitest run` fails: `child.channel?.unref is not a function` when starting a forks worker.
- `@effect/vitest` 4.1.5 provides `it.effect`, `it.prop` and `it.effect.prop`.
- **Effect's `Arbitrary` is Effect's own generator, not fast-check.** The `effect` package has no dependencies. `effect/Arbitrary` is marked `@stability unstable`. `it.prop("name", [SomeSchema], ([value]) => ...)` takes Schemas directly, which is how property tests are built from the app's own Schemas.
- **The Foldkit Vite plugin works under Bun.** A minimal Foldkit app (`foldkit` 0.171.0, `@foldkit/vite-plugin` 0.29.1, `vite` 8.3.8) built with both `bun run vite build` and `bun --bun vite build`. A Story test (`foldkit/story`) passed under Vitest 5.1.1. The plugin is used as `plugins: [foldkit()]`.

### Mutation testing

- **Stryker 10.1.1 works with Vitest 5 under Bun, with one workaround.** Its sandbox step rewrites `tsconfig.json` using the TypeScript JS API (`ts.parseConfigFileTextToJson`). TypeScript 7 has no JS API, so the run crashes.
- Workaround: set `"tsconfigFile"` in the Stryker config to a file that does not exist. The rewrite is skipped and the sandbox run completes. `--inPlace` also works but mutates source files while it runs, so it is not used.
- The `break` threshold sets exit code 1 when the score is below it. Confirmed.
- `@stryker-mutator/typescript-checker` is not used: it needs the TypeScript JS API.
- Open for Part C: whether the sandbox, which copies only the package, breaks a tsconfig `extends` that points outside the package. Vitest does not type-check, so this is expected to be harmless.

### Other tools

- **knip 6.48.0** parses with oxc and does not depend on TypeScript, so TypeScript 7 is no problem. It reports the tsconfig plugin name `@effect/language-service` as an unlisted dependency; add it to `ignoreDependencies`.
- **Oxfmt 0.80.0** works with no config and reads `.oxfmtrc.json` (`oxfmt --init` writes one).
- **lefthook 2.2.2** installs and runs under Bun. It is a native binary.
- **GitHub Actions:** `actions/checkout@v7.0.1`, `oven-sh/setup-bun@v2.2.0`, `actions/setup-node@v7.1.0`. CI needs Node as well as Bun because Vitest and Stryker run on Node and the Oxlint preset loads `oxlint.config.ts` with Node (22.18 or later).

## Decisions made in this spec

Change any of these by saying so; otherwise later parts follow them.

1. **Scripts call the tools directly**: `effect-tsgo tsc`, `oxlint`, `oxfmt`, `vitest`, `knip`, `stryker`. There is no Vite+ (`vp`) layer.
2. **Each workspace package starts with a placeholder module and one test**, so every rail has something to run on. Foldkit, Alchemy and Cloudflare dependencies are not added in M0. They arrive with the milestone that uses them (M2 for engine and infra, M3 for web), along with their own rails (Foldkit Story and Scene tests, integration stacks, tracing).
3. **Workspace package names** are `@aemeth/core`, `@aemeth/blocks`, `@aemeth/engine`, `@aemeth/web` and `@aemeth/infra`. All private.
4. **The import boundary is enforced twice**: an Oxlint `no-restricted-imports` override for `packages/core/**` that bans `@aemeth/*` imports and relative imports that leave the package, and a check that `packages/core/package.json` lists no workspace dependency.
5. **Every rail is shown to fail once.** For each rail, Part B or C plants a violation, confirms the command exits non-zero with a useful message, then removes the violation. The result is recorded in the group's evidence in `plan.md`.
6. **Proposed mutation thresholds:** `high: 90`, `low: 80`, `break: 80`. The owner sets the final `break` value, since M1 must meet it. *The owner kept `break: 80` on 2026-11-23.*
7. **The Claude Code hook asks for approval** before any Edit or Write under `packages/core/src/invariants/`, through a `PreToolUse` hook in `.claude/settings.json` that returns `permissionDecision: "ask"` with a reason. It does not block outright, because adding an invariant is allowed.
8. **CI uses Node 26**, the version used locally.

### What Part B changed in this spec

Found while building Part B on 2026-11-23. Evidence is in [../plan.md](../plan.md#active-milestone-m0-workspace-and-rails).

- **`@effect/tsgo` override paths resolve from the tsconfig that declares the plugin**, which is the root `tsconfig.base.json`. Its default override, `src/**/*.ts`, matched no file in the packages, so it is `**/*.ts`. **Every matching override applies and their options merge**, whatever their order: with the test override carrying only `allowedUnstableApis` and placed first or last, a floating Effect in a test file still failed, and `@effect/vitest` raised no warning. The README does not say this, so the test was the check.
- **`unstableApiUsage` stays on everywhere.** Test files get `allowedUnstableApis: ["@effect/vitest"]` in place of turning the rule off, so any other unstable API still fails the build. Warnings fail `tsc` by default; suggestions do not.
- **Oxfmt skips `*.md`.** It pads Markdown tables, which would rewrite every planning document. Code, JSON and config are formatted with Oxfmt's defaults (semicolons, double quotes). Both choices confirmed by the owner on 2026-11-23.
- **The `package.json` half of decision 4 is a test,** `packages/core/src/boundary.test.ts`. It imports `../package.json`, decodes it with a Schema, and fails on any `@aemeth/*` name, or any `workspace:`, `file:`, `link:` or `portal:` range, in all four dependency sections. For this, `packages/core/tsconfig.json` has `rootDir: "."`, includes `package.json`, and sets `resolveJsonModule`.
- **The relative-import ban is a pattern, in two overrides:** `../` for files at the top of `packages/core` (config files are not in core's tsconfig, so lint is their only check), and `../../` for files below it. It also blocks a `../../` import that stays inside core from three or more folders deep; use a shorter path if that ever happens. `no-restricted-imports` does not see dynamic `import()`; core has no reason to use one.
- **`effect` is also pinned at the root,** at the packages' version, so the peer of `@effect/vitest` cannot resolve to a different copy.
- **`tsc -b --clean` does not remove declarations for deleted sources.** After planting files, delete their output under `dist/` by hand.
- **Bun 1.4 uses its isolated linker:** `packages/core/node_modules` holds only `effect`. Test tooling (`vitest`, `@effect/vitest`) is a root devDependency, which knip accepts.
- **`oxlint.config.ts` and `vitest.config.ts` are linted and formatted but not type-checked,** since no tsconfig project includes them.

### What Part C changed in this spec

Found while building Part C on 2026-11-23. Evidence is in [../plan.md](../plan.md#active-milestone-m0-workspace-and-rails).

- **The `extends` question is answered: it breaks.** Run from `packages/core`, Stryker's sandbox is `packages/core/.stryker-tmp/sandbox-*/`, so `../../tsconfig.base.json` points inside core, and Vite's transform fails (`TSCONFIG_ERROR … Tsconfig not found`). Vitest does not type-check, but Vite still loads the tsconfig. **Fix:** `bun run mutate` runs `stryker run packages/core/stryker.config.json` from the repository root. The sandbox copies the repository, so every relative path holds. The config stays in `packages/core`; `mutate` globs and `vitest.dir` name `packages/core`.
- **Stryker needs `"plugins": ["@stryker-mutator/vitest-runner"]`.** It finds plugins beside its own install, and Bun's isolated linker keeps them apart (`Cannot find TestRunner plugin "vitest"`).
- **A brand name cannot be mutation-tested.** `Schema.brand("StepId")` mutated to `Schema.brand("")` survived: decode errors and the JSON Schema are identical, so the name exists only in types. It is marked `// Stryker disable next-line StringLiteral` with that reason. Expect one per brand in M1. `ignoreStatic` is not the fix: it would skip every Schema mutant.
- **lefthook's `postinstall` runs under Bun** (it is on Bun's trusted list). On install it wrote an example `lefthook.yml` and a `prepare-commit-msg` hook. The example was replaced; the extra hook calls lefthook with no jobs, so it does nothing. The root `prepare` script, `lefthook install`, stays as the stated way in.
- **The pre-commit jobs run on the whole project, not on staged files.** Typecheck and type-aware lint need the whole program anyway. Lefthook skips every job when nothing is staged; `bunx lefthook run pre-commit --all-files` runs them by hand.
- **The invariants hook also covers Bash**, which decision 7 did not mention: without it, a `sed -i` or a redirect into the folder bypasses the check. A Bash command that only reads the folder will ask too. The hook **fails closed**: input it cannot decode asks rather than allows.
- **Changed after the close (2026-11-23, owner's choice):** asking on any Bash command that named the folder prompted on reads, and on scripts that wrote docs mentioning the path, which made auto mode worse. Bash no longer asks up front. A `PreToolUse` hook fingerprints the folder's files (SHA-256 of each) before every Bash command, and a `PostToolUse` hook compares after it; any changed, added or removed file returns `decision: "block"` with a reason, and a `systemMessage` the owner sees. Edit, MultiEdit, Write and NotebookEdit still ask first, by exact file path. The trade-off: a Bash write is reported after it happens, where git can undo it, not asked about before. A missing snapshot is reported too. Shown by hand: a read gives nothing; an added file and a changed `README.md` are each reported by name.
- **The hook is TypeScript run by Bun,** so it is type-checked and linted like the rest. `.claude/hooks/tsconfig.json` is a project in the root `tsconfig.json` with `types: ["bun"]` (`@types/bun` 1.4.5), and knip lists the hook as an entry.
- **Claude Code reads `.claude/settings.json` hooks at session start.** A test write in the session that created the file was not stopped. The live check needs a new session.
- **Do not run Stryker from inside `packages/core`.** A run that crashes leaves its sandbox behind, and in `packages/core/.stryker-tmp/` the Vitest project for core picks it up and fails on it. A completed run, even one below `break`, removes its sandbox. From the root, a crash leaves `.stryker-tmp/` at the root, outside the Vitest project globs and in `.gitignore`.
